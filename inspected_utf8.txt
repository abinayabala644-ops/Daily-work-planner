=== SECTION: scope ===
<section id="scope">
        <h2><span class="section-num">05.</span> Scope Breakdown</h2>

        <h3>5.1 In Scope (Version 1.0)</h3>
        <ul>
          <li>Single-page, responsive web application accessible via desktop and tablet browsers.</li>
          <li>Daily calendar view representing the 9:00 AM to 6:00 PM workday, reusable every day.</li>
          <li>8 designated working slots: 9-10 AM, 10-11 AM, 11-12 PM, 12-1 PM, 2-3 PM, 3-4 PM, 4-5 PM, 5-6 PM.</li>
          <li>Each working slot contains:
            <ol>
              <li>A text input box for writing planned work.</li>
              <li>A status checkbox.</li>
              <li>A "Completed" button with visual tick mark.</li>
              <li>A "Not Completed" button with visual cross/wrong mark.</li>
            </ol>
          </li>
          <li>Enforced mutual exclusivity between "Completed" and "Not Completed" buttons per slot.</li>
          <li>Fixed non-interactive Lunch Break row from 1:00 PM to 2:00 PM (no text field, no checkbox, no action buttons).</li>
          <li>Pending Work section placed prominently at the bottom of the page.</li>
          <li>Manual creation of multiple Pending Work records with fields for:
            <ol>
              <li>Associated time slot when the work was pending.</li>
              <li>Work name and detailed multi-line text description.</li>
              <li>An independent status checkbox in the corner of each record.</li>
            </ol>
          </li>
          <li>Absolute enforcement of zero automated data generation or transfer.</li>
        </ul>

        <h3>5.2 Out of Scope (Explicitly Excluded)</h3>
        <ul>
          <li><strong>No Automatic Task Migration:</strong> Marking an hour as "Not Completed" shall never create or pre-populate an entry in the Pending Work section.</li>
          <li><strong>No Third-Party Calendar Integrations:</strong> No synchronization with Google Calendar, Microsoft Outlook, or Apple iCal.</li>
          <li><strong>No Automated Alarms / Push Notifications:</strong> No auditory chimes, browser push alerts, or timer countdown popups.</li>
          <li><strong>No Multi-User Collaboration:</strong> No team sharing, task delegation, or role-based permission sets.</li>
          <li><strong>No Stopwatch / Time Tracker:</strong> No background seconds-counter or punch-in/punch-out utility.</li>
        </ul>
      </section>

<section id="user-flow">
        <h2><span class="section-num">09.</span> Detailed User Flow</h2>
        <p>The daily operational lifecycle of the planner follows seven structured chronological steps:</p>

        <div class="flow-steps">
          <div class="flow-card">
            <div class="flow-index">1</div>
            <div class="flow-details">
              <h4>Morning Initialization</h4>
              <p>The user opens the Daily Work Planner web page at the beginning of the workday. The screen renders 8 sequential working time slots and the fixed 1:00 PM ΓÇô 2:00 PM Lunch Break row in pristine ready state.</p>
            </div>
          </div>

          <div class="flow-card">
            <div class="flow-index">2</div>
            <div class="flow-details">
              <h4>Planning Hour-by-Hour Commitments</h4>
              <p>The user clicks directly into the text boxes for slots (e.g., 9:00 AM ΓÇô 10:00 AM) and types specific goals (e.g., "Draft Q4 Roadmap"). The user repeats this for desired hours across the 9 AM to 6 PM day.</p>
            </div>
          </div>

          <div class="flow-card">
            <div class="flow-index">3</div>
            <div class="flow-details">
              <h4>Midday Execution & Status Marking</h4>
              <p>As each working hour completes, the user returns to the page. If the task succeeded, the user marks the slot's checkbox and clicks the "Completed" (tick Γ£ô) button, which illuminates in its active state.</p>
            </div>
          </div>

          <div class="flow-card">
            <div class="flow-index">4</div>
            <div class="flow-details">
              <h4>Handling Unfinished Tasks (Mutual Exclusivity)</h4>
              <p>If an urgent meeting prevented work during 2:00 PM ΓÇô 3:00 PM, the user clicks "Not Completed" (cross Γ£ù). If "Completed" was previously selected, the system immediately unsets it. No automatic entries are created anywhere.</p>
            </div>
          </div>

          <div class="flow-card">
            <div class="flow-index">5</div>
            <div class="flow-details">
              <h4>Manual Logging into Pending Work</h4>
              <p>The user scrolls down to the Pending Work section. The user manually types the pending slot ("2:00 PM - 3:00 PM"), the work name ("Client Review"), and types a detailed note ("Review halted awaiting client assets"). The user clicks "Add Pending Work".</p>
            </div>
          </div>

          <div class="flow-card">
            <div class="flow-index">6</div>
            <div class="flow-details">
              <h4>Managing Backlog Records</h4>
              <p>The new pending entry appears in the list with its own dedicated corner checkbox. The user can add additional pending entries sequentially. When an item is eventually addressed later, its corner checkbox is checked off.</p>
            </div>
          </div>

          <div class="flow-card">
            <div class="flow-index">7</div>
            <div class="flow-details">
              <h4>End-of-Day Review & Next-Day Reuse</h4>
              <p>The user performs a final visual scan of the day's 8 slots and pending list to measure performance before closing the planner or refreshing it for the next day's schedule.</p>
            </div>
          </div>
        </div>

=== SECTION: assumptions-risks ===
<section id="assumptions-risks">
        <h2><span class="section-num">10.</span> Assumptions, Risks, and Dependencies</h2>

        <h3>10.1 Assumptions</h3>
        <ul>
          <li><strong>Deliberate Intentionality:</strong> Users actively prefer typing pending notes manually to reinforce awareness of uncompleted work, rather than relying on automated syncing.</li>
          <li><strong>Standard Workday Hours:</strong> The default 9:00 AM to 6:00 PM hours with lunch from 1:00 PM to 2:00 PM sufficiently match the daily schedule of the target user base.</li>
          <li><strong>Modern Browser Environment:</strong> Users will access the application through standard HTML5-compliant web browsers with JavaScript enabled.</li>
        </ul>
